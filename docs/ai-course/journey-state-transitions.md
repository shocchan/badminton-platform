# 初回Journeyの状態遷移と保存順序（Phase 2E-1.14 §2 監査）

再読込・戻る・二重操作で壊れないようにするには、まず「何を・どこへ・どの順で・何回・
どの冪等キーで」保存しているかが分かっている必要がある。これはその棚卸し。

保存先はすべて `sessionStorage`（検証中はsandbox名前空間）。**正式なDB保存はまだ無い。**

## 保存先キー

| キー | 中身 | 消してよいか |
|---|---|---|
| `ai_course_vocab_preview_v1` | 語ごとの接触・問題結果・自己評価 | **不可**（学習記録） |
| `ai_course_vocab_schedule_preview_v1` | 復習予定（翌日/3日後/7日後） | **不可**（学習記録） |
| `ai_course_first_run_v1` | 初回Journeyの現在ステップ・目的 | 可（Journey用） |
| `ai_course_journey_task_v1` | 診断・練習との往復契約 | 可（Journey用） |
| `ai_course_journey_sandbox_v1` | 検証用の分離名前空間 | 可（検証用） |

## 診断の書き込み順序

| # | 出来事 | 書き込み | 冪等性 |
|---|---|---|---|
| 1 | Step2で「確認を始める」 | 契約: activeTaskType=diagnostic・status=in_progress・token発行 | 同じtaskIdで再開始しても契約は1つ |
| 2 | 問題表示 | なし | — |
| 3 | 選択肢を選ぶ | **なし（componentのstateのみ）** | 未確定なので再読込で消える＝確定扱いにしない |
| 4 | 確定 | 進捗: 問題結果 | 語＋回数で追記（同じ回答の再送は新しい結果になる） |
| 5 | 最終回答 | 同上 | 同上 |
| 6 | 診断結果確定 | 進捗: 診断outcome | パックごとに上書き（冪等） |
| 7 | 契約完了 | 契約: status=completed・token消費・completedTaskIds追加・snapshot保存 | **journeyId＋taskId＋未使用tokenの3点一致でのみ成立** |
| 8 | Journey更新 | Journey: step=practice | `completeCheck()` は同じstepへ何度書いても同じ |
| 9 | route遷移 | なし（URLのみ） | — |

## 練習（今日のことば）の書き込み順序

| # | 出来事 | 書き込み | 冪等性 |
|---|---|---|---|
| 1 | Step3で「最初の練習を始める」 | Journey: step=done ／ 契約: practice・in_progress・token発行 | — |
| 2 | card表示 | なし | — |
| 3 | card完了（確認する） | 進捗: 接触記録 | 同じ語へ何度でも追記可（回数の意味） |
| 4 | quiz選択 | **なし（stateのみ）** | 未確定 |
| 5 | 正誤確定 | 進捗: 問題結果 ／ **予定: 誤答→翌日・正解→7日後** | 予定は語ごとに1件を更新（同日再正解では段階を進めない） |
| 6 | assess選択 | 進捗: 自己評価 ／ 予定: まだ不安→翌日・覚えた→変更なし | 語ごとに上書き（冪等） |
| 7 | 次の語へ | なし | — |
| 8 | 3語目完了 | なし（画面遷移のみ） | — |
| 9 | 「今日の学習を終える」 | 契約: completed・token消費・completedTaskIds追加・snapshot保存 | 3点一致でのみ成立 |
| 10 | Journey更新 | Journey: step=done | 冪等 |
| 11 | route遷移 | なし | — |

## 中間失敗と再開地点

| 失敗地点 | 起きること | どこから再開すべきか |
|---|---|---|
| 3・4（未確定の選択） | 保存が無い | その語の同じフェーズの先頭から。**正解扱いにしない** |
| 5の直後 | 問題結果と予定はある・自己評価が無い | assessから。予定を作り直さない |
| 6の直後 | その語は完結 | 次の語から |
| 9の前 | 全語の学習記録と予定はある・契約は in_progress | 契約完了の再試行。**学習をやり直させない** |
| 9と10の間 | 契約は completed・Journeyは practice のまま | Journeyのstepだけ修復。tokenを再消費しない |
| 10と11の間 | 状態は完結・画面だけ前 | Step4を表示するだけ。完了処理を再実行しない |

**再開の原則**: 保存済みの事実からのみ再開を決める。URLやrouteだけで完了扱いにしない。
取得できなかった値を0と断定しない。

## 現時点で分かっている弱点（2E-1.14で扱う）

1. 練習の `idx` と `phase` は component state のため、**再読込すると必ず1語目のcardへ戻る**。
   学習記録と予定は保存済みなので損失は無いが、「続きから」にはならない。
2. 上記9〜11の中間失敗に対する明示的なRecovery関数がまだ無い
   （契約側の二重完了防止はあるが、「契約completed・step未更新」を修復する経路が無い）。
3. 復習予定の冪等キーは「語ID」単位で、同じ日に同じ操作を繰り返したときの区別を持たない。
