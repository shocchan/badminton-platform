# 管理画面は「何が確認できればいいか」

2026-08-23。CEO報告「管理ページをまだ使いこなせていない」「情報が多くて、ちょいとチェックが難しい」を受けて、
機能から考えるのをやめ、**運営で実際に起きたこと**から必要なものを決め直した。

## 決め方

作った機能を並べるのではなく、**この事業で実際に起きた出来事**を並べ、
「起きたとき、CEOは何を知る必要があったか」だけを残す。起きていないことのための画面は作らない。

## 実際に起きたこと（2026-07〜08・本番データ）

| 起きたこと | 実例 | 知る必要があったか |
|---|---|---|
| 600円を買ったのに、一度も学習を始めない | 8/19 の購入者 | **要る**。24時間で気づいて声をかけたい |
| 決済画面まで行って支払わずに消えた | 8/20×2・8/21×1（live） | **要る**。3日で3人＝取りこぼしの本体 |
| アカウントを発行したのに一度もログインしない | wang（8/18発行） | **要る**。渡し方の問題かもしれない |
| セッションが6時間以上そのまま | 監視が8/22に検知 | **要る**。ただし機械が拾えるので通知でよい |
| 受講権の期限が近い | 設計上いずれ必ず起きる | **要る**。延長するか決めるのはCEOだけ |
| AI会話の原価がかさむ | 実測 $8.07/時間 | **要る**。月いくらかを毎日ではなく毎朝ざっくり |
| 生徒が同じ束で何日も不合格 | 救済を配線済み（8/22） | **要る**。人が声をかける判断のため |
| 生徒から問題報告 | ai_issue_reports | **要る**。放置が一番まずい |
| 教材の中身を1件ずつ確認したい | 随時 | 要るが**毎朝ではない** |
| 上限設定・テストデータ削除 | まれ | 要るが**奥でいい** |

## 3つに分ける

1. **毎朝5分の点検**（＝点検ボード。開いた瞬間に全部見える）
   - 今すぐ手を打つ人（買ったのに始めない／期限が近い／未ログイン／詰まっている／問題報告）
   - お金が落ちなかったところ（支払い途中で消えた件数）
   - お金（今月の売上・AI原価）
   - 機械からの知らせ
2. **その場の操作**（生徒1人のページ。ボードの行から直接ひらく）
   - 期間を伸ばす・止める／メモを書く／目標や時間を調整する／アカウントを発行する
3. **たまに使うもの**（奥に置く。毎朝の導線に出さない）
   - 教材レビュー／上限設定／テストデータ削除／コストの内訳

## 原則

- **数字より先に「やること」。** 数字だけ並べても行動は決まらない。人名と動詞を先に出す。
- **無いときは「ありません」と言い切る。** 空の枠を並べると、毎朝それを読む手間が増える。
- **タブを回らせない。** 情報を探しに行かせた時点で使われなくなる（実際そうなった）。
- **個人情報は最小限。** ボードに出すのは学習IDだけ。メール・氏名・会話の中身は載せない。
- **毎朝、勝手に最新になる。** 開くたびに人が更新操作をするなら、それは使われない。

## いまの実装

- ボードの生成: `node scripts/ai-course/render-ops-board.mjs`（読み取りのみ）
- 毎朝の自動更新: Claude Code のスケジュールタスク `ai-course-ops-board`（同じURLへ貼り直す）
- 管理ページ（5タブ）はそのまま残す。**入口をボードにして、操作のときだけ降りる**
