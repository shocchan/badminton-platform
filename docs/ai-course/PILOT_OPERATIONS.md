# PILOT OPERATIONS — 有料Pilot（3名限定）の運用手順

**この手順書は、技術者でなくても1人の学習者を有料Pilotへ登録し、学習開始まで案内できることを目的とする。**

判断基準は `docs/ai-course/PRODUCT_CANON.md`。迷ったらそちらが優先する。

- 対象URL（Pilot中はstaging）: https://staging.badminton-platform.pages.dev/ja/ai-course?app=1&v2=1 （中国語は `/zh/`）
- 決済・招待は**手動**でよい。今回は自動化しない
- **合格保証はしない。誇大な表現はしない。**（canon §0）

---

## 0. 用語

| 用語 | 意味 |
|---|---|
| learner | 学習者のアカウント（`ai_learners` の1行） |
| 招待コード | `ai_course_invites` の1行。これが無いと初回ログインできない |
| V2 | 今回の Adaptive Adventure。`settings.adventureV2.enabled` で learner ごとに ON |
| 冒険 | 今日やること1セット（Today Adventure） |

2. **申込時点で必ず伝えること**
   - Pilot版であり、機能が増減する可能性があること
   - 合格を保証するものではないこと
   - 休会・解約・返金の条件（下記URL）
   - AIが学習記録を使うこと（AI利用の開示ページ）

## 2. 支払いを確認する

Pilotは**手動決済**。銀行振込／PayPay／WeChat Pay など、しょっちゃんが普段使う方法でよい。

- 入金を確認してから招待コードを発行する（先に発行しない）
- 領収書・受領の連絡を必ず送る
- **Stripeの本番決済は今回使わない**（実装は休眠中）

## 3. 同意を確認する

次の一文を送り、返信をもらってから登録する（記録として残す）。

> 利用規約・プライバシーポリシー・AI利用の開示・キャンセルポリシーを確認しました。
> Pilot版であること、合格保証ではないことを理解しています。

## 4. 招待コードを発行する

Pilotの枠は1人1枠。ラベルは英大文字1文字（`A`〜`Z`、最初の3人は `A` / `B` / `C` を使う）。
同じラベルを2人に使い回さないこと（`--reissue` が別人のコードを無効化してしまう）。

```bash
cd ~/badminton-aicourse   # ⚠️ スクリプト類はこのworktreeが最新（badminton-platformではない）

# まず確認だけ（--confirm を付けなければ実行されない）
node scripts/ai-course/issue-pilot-invites.mjs \
  --learner A --email <学習者のメール> --expires 2026-08-22   # 期限は開始日+1週間を目安に

# 内容を確認したら --confirm を付けて実行
node scripts/ai-course/issue-pilot-invites.mjs \
  --learner A --email <学習者のメール> --expires 2026-08-15 --confirm
```

- `--email` を付けたコードは**そのメールでしか使えない**（誤配布に強い）
- `--expires` は必須。**期限のないコードを作らない**
- 誤って配ってしまったら、同じ枠へ `--reissue --confirm` を付けて再発行すると
  古いコードは自動で無効化される（コマンドは実行後に画面へ表示される）
- 発行したコードは学習者に個別に送る（公開の場に貼らない）

## 5. 学習者に送る案内文（そのままコピーして使える）

> こんにちは。AI日本語コースへようこそ。
>
> 1. こちらを開いてください: https://staging.badminton-platform.pages.dev/ja/ai-course?app=1&v2=1
>    （中国語表示は https://staging.badminton-platform.pages.dev/zh/ai-course?app=1&v2=1 ）
> 2. メールアドレスを入れて、招待コード「◯◯◯◯」を入力してください
> 3. メールに**8桁の数字**が届きます。それを入力するとログインできます
> 4. 最初に、目標・試験の予定日・1日に使える時間・案内の先生を選びます
> 5. そのあと診断（10分ほど）をします。**わからない問題は飛ばして大丈夫です。**
>    正確に測るためのものなので、できなくても問題ありません
> 6. 診断が終わると、あなた専用の学習ルートができます
> 7. あとは毎日ホームを開いて、**いちばん上のボタンを押すだけ**です。今日やることはこちらで決めます
>
> マイクを使う会話練習があります。iPhoneやAndroidのブラウザでも使えます。
> 困ったことがあればいつでも連絡してください。

**8桁OTP**であることは必ず伝える（6桁だと思って待つ人がいる）。

**コース別の一言を必ず添える**（4.の目標選択で迷わせない）:

- N2+帰化面接コースの人 →「目的は **JLPT合格**、目標は **N2** を選んでください。
  帰化面接の練習コーナーは、設定が終わったあとこちらで開放します（成長マップに出ます）」
- N3コースの人（試験中心） →「目的は **JLPT合格**、目標は **N3** を選んでください」
- N3コースで**会話重視**の人 →「目的は **『JLPTも会話も伸ばしたい』（両方）**、目標は **N3** を
  選んでください。試験と会話の両方が毎日の冒険に入り、成長マップで会話ルートにも切り替えられます」

**選び間違えたら**: 本人の画面「その他の学習」→「目的・レベルを変える（準備をやり直す）」で
本人がいつでも選び直せる（学習記録・攻略の実績は消えない。診断だけもう一度受ける）。

## 6. V2を有効にする

**スクリプトは使わない。学習者自身が有効にする**（案内文のURLに `?v2=1` が
入っているので、開いて「冒険を始める」を押すだけ。目標・先生・診断はそのまま
本人がオンボーディングで設定する）。

> 🚨 **`seed-adventure-profile.mjs` を実学習者に実行しないこと。**
> あれはstaging検証用fixture（`.invalid`ドメインの合成learner）専用で、
> settings全体を偽の完了済み診断（固定スコア・固定試験日）で上書きする。
> 実行すると本人の目標・先生選択・診断・発行済みの答案用紙・面接特訓が全部消える。
> （2026-08-08の監査で本docが誤ってこのスクリプトを案内していたことが判明し修正。
> スクリプト側にも `.invalid` 以外を拒否するガードを入れた）

## 6b. コース専用機能を発行する（該当者のみ）

**N2+帰化面接コースの人**には、本人がV2オンボーディングを終えたあとに2つ発行する:

```bash
cd ~/badminton-aicourse   # ⚠️ 新スクリプトは aicourse worktree にある（badminton-platformではない）

# ① 帰化面接の表現特訓（発行しないと本人の画面に一切出ない）
node scripts/ai-course/issue-interview-prep.mjs --email <本人のメール> --confirm

# ② 過去問の答案用紙（用紙JSONの例: docs/ai-course/answer-sheets/example-paper.json）
node scripts/ai-course/issue-answer-sheet.mjs --email <本人のメール> \
  --paper docs/ai-course/answer-sheets/example-paper.json --confirm
# 問題そのものはWeChatで本人へ送る（アプリには問題を置かない）
# 採点も必ずWeChatで返す: 正解未登録で発行した用紙は、提出後にアプリへ採点を
# 書き戻す手段が無い（アプリの提出履歴は「採点は先生からWeChatで届きます」表示のまま）
```

どちらも `--confirm` なしで dry-run できる。**発行チェック**: 本人の成長マップ下部
「特別な場所」に「帰化面接の表現特訓」「過去問の試験場」が出ていれば成功
（試験場は目標N2の人にだけ出る）。

> ⚠️ **発行のタイミング（重要）**: 本人がアプリを開いている間に発行しない。
> アプリはステップ完了・マークシートの解答1タップごとに settings 列を**丸ごと上書き保存**し、
> learner の再読込は初回ロードの1回だけのため、発行直後に本人が何か操作すると
> いま発行した answerSheets / interviewPrep が**無言で消える**（スクリプトは✅表示のまま）。
> 必ず次の手順で発行する:
> 1. 本人がアプリを使っていない時間帯（深夜・早朝など）に発行する
> 2. 発行後、本人に「アプリを一度閉じて、開き直してください」と伝える（開き直しで新しい settings が読み込まれる）
> 3. **残存確認**: 数分後〜翌日に同じコマンドを `--confirm` なしでもう一度実行する。
>    答案用紙 → 「refuse: paperId "..." は既に発行済み」と拒否されれば残っている。
>    面接特訓 → 「発行状態=<日時>」が表示されれば残っている。
>    消えていた（未発行表示に戻っていた）場合は、本人がアプリを閉じたのを確認してから再発行する。

**N3コースの人**には発行するものはない（文法・語彙・読解・聴解はV2に内蔵）。

**ゼロ初心者（かな未習）の人**への注意: アプリにはひらがな・カタカナの学習モジュールが
まだ無く、基礎キャンプは漢字語の問題から始まる。かなが読めない人は最初の単元で詰まるため、
開始前に必ず:
1. WeChatで五十音表（ひらがな・カタカナ）と読み練習資料を送る
2. 最初の1週間は伴走メッセージで「1日1〜2行（あ行→か行…）」のかな練習を出す
3. かなが一通り読めるようになってから基礎キャンプへ誘導する
（アプリ内かな導入モジュールは開発バックログ。既存の readingKana / readingRomaji データから生成可能）

## 7. 学習が始まったか確認する

管理画面 `/ja/ai-course/admin` で次を見る。

- learner が一覧に出ているか
- 診断が完了しているか
- 冒険を1回でも完了しているか

**初日に冒険を1回完了できていれば成功。** できていなければ連絡して詰まりを聞く。

## 8. AI会話が使えるか確認する

学習者に1回やってもらい、次を聞く。

- マイクの許可が出せたか
- 先生の声が聞こえたか
- 会話のあとレポートが出たか

聞こえない場合の案内: ①ブラウザを最新にする ②イヤホンを外す
③別のブラウザ（Safari↔Chrome）を試す ④それでも駄目ならテキスト会話へ切り替える

## 9. しょっちゃんが進捗を見る

| 見たいもの | 場所 |
|---|---|
| 全体の状況・利用状況 | `/ja/ai-course/admin` |
| その学習者の今週 | 学習者の画面の「今週のまとめ」（本人に見せてもらう／画面共有） |
| **次のレッスンで扱う候補** | 学習者の画面「先生レッスンの準備」（最大3件に絞られている） |

レッスン前に見るのは**「先生レッスンの準備」の3件だけでよい**。
学習履歴を全部見る必要はない（canon §7: AIが量を、人が難所を担当する）。

## 10. トラブル時の対応

| 症状 | 対応 |
|---|---|
| ログインできない | 招待コードの有効期限・メール一致を確認。OTPは**8桁** |
| OTPメールが届かない | 下の「OTPメールが届かないとき」の手順へ |
| 画面が古い | URLの末尾に `&cb=123`（数字は何でもよい）を付けて再読み込み |
| 会話の声が出ない | §8の案内。直らなければテキスト会話で継続してもらう |
| 会話が始まらない・エラー | その日はテキスト会話か問題演習で継続。こちらへ連絡してもらう |
| 音声（聴解）が再生できない | 端末の音量とマナーモードを確認。別ブラウザを試す |
| 問題がおかしい | 問題のIDか画面のスクリーンショットをもらう。review queue へ入れる |
| 学習が進まない | 1日の時間を5分へ下げる提案をする（設定から変更できる） |
| 端末を変えたら今日の進捗が消えている | 前の端末でアプリを一度開いてもらう（未送信の記録が自動で再送される）。学習は普段使う1台で行うよう案内する（複数端末の同時併用は、古い端末の保存が新しい進捗を上書きすることがある） |

**既知の制限（設計判断・2026-08）**

- 相棒（ナミ／フク老師／カジ）の emphasis 重みはクエスト構成に未反映（型定義上の宣言のみ）。hybrid（総合）の1日クエストの会話比率は固定（会話step1つ）。「もっと会話を増やしたい」という学習者には、目的を「会話」へ変更する（オンボーディングをやり直す）案内をする。

**OTPメールが届かないとき**（qq.com / 163.com は迷惑メール判定されやすい）

1. まず**迷惑メールフォルダ**を見てもらう（QQ邮箱は「垃圾箱」、163は「垃圾邮件」）
2. 60秒待って、ログイン画面の**「再送」**ボタンを押してもらう
   （送信は60秒に1回・**1時間に8回まで**。上限に達したら1時間待つ）
3. 送信リクエストがサーバーに届いているか確認する（読み取りなので安全）:

```bash
node scripts/ai-course/remote-sql.mjs \
  --sql "select email, last_sent_at, sent_in_window from public.ai_otp_throttle where email = lower('<本人のメール>');" \
  --label "otp delivery check"
```

   - 行が無い／`last_sent_at` が古い → 送信操作がサーバーに届いていない（回線・メールの打ち間違いを疑う）
   - `last_sent_at` が直近 → サーバーは送信済み。メール側（迷惑メール判定・受信拒否）で止まっている
4. Supabaseダッシュボード（プロジェクト `jdkwijdphlkrcoiggfqw`）の **Logs → Auth** で送信エラー（bounce・rate limit）が出ていないか見る
5. それでも届かないなら、**Gmailなど別のメールアドレスで招待を再発行**する（まだ初回ログインしていない人に有効。旧コードは自動で無効化される）:

```bash
node scripts/ai-course/issue-pilot-invites.mjs \
  --learner A --email <新しいメール> --expires <期限> --reissue --confirm
```

   再発行したら、新しいコードと新しいメールで §5 の案内をやり直す
6. **登録済み（一度ログインできた）人**のメール変更は、Supabaseダッシュボードの Authentication → Users で本人のメールを変更する（変更後は新メールでそのままOTPログインできる。招待コードの再発行は不要）

**AI側の障害（OpenAI・Supabaseの停止）が疑われるとき**

1. 学習者へ「今日はAI会話をお休みして、問題演習だけにしてください」と伝える
2. 問題演習・読解・聴解は**外部AIに依存しない**ので、そのまま使える
3. 復旧を待ってから会話を再開する

## 11. 休会・解約・返金

- 条件は `/ja/ai-course/cancel-policy` に書いてある。**この内容を超える引き止めはしない**

## 12. learnerを停止する（休会）

⚠️ ここから先はDBを直接触る。`remote-sql.mjs` は**書き込みのとき `--write` と `--label` が必須**で、
ラベルは監査ログ（`docs/ai-course/production/remote-apply-audit.log`）へ残る。
「誰のために何をしたか」が後から分かる文言にすること。

```bash
# 停止すると新しいセッションを開始できなくなる。データは残る。
# 書き込みなので --write と --label が必須（監査ログに残る）
node scripts/ai-course/remote-sql.mjs \
  --sql "update public.ai_learners set is_active = false where id = '<learnerId>';" \
  --write --label "pilot pause <名前>"
```

再開するときは同じ形で `is_active = true` に戻す。
実行前に、まず読み取りで対象を確かめると安全:

```bash
node scripts/ai-course/remote-sql.mjs \
  --sql "select id, display_name, is_active from public.ai_learners;" --label "pilot check"
```

## 13. learnerを削除する（退会）

**削除は元に戻せない。** 本人の明確な依頼があるときだけ行う。

1. 本人へ「学習記録もすべて消えること」を伝え、同意をもらう
2. 削除する

```bash
# 発話ログだけ消す場合（アカウントは残す）
node scripts/ai-course/remote-sql.mjs \
  --sql "select public.ai_admin_delete_utterances('<learnerId>');" \
  --write --label "pilot delete utterances <名前>"
```

アカウントごと消す場合は `/ja/ai-course/account-deletion` の手順に従う。
**手作業でauth.usersを直接消さない**（関連データが取り残される）。
