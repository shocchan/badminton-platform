## Case と記録欄
先生が話している最中に行う。各 Case は 2〜3 回ずつ試し、パネルの数値を控える。

| Case | やること | 期待 | 結果（◯/×・パネルの数値・気づき） |
|---|---|---|---|
| A | 小さく「あ」／「うん」「うんうん」 | 先生は止まらない。「無視した」が増え「止めた」は増えない。先生が話し終わった直後に「うん」への返事が始まらない | |
| B | 咳・深い呼吸・机を軽く叩く・近くで物音 | 先生は止まらない。「止めた」は増えない | |
| C | **2 秒以上続けて**話しかける（例:「ちょっと待ってください、それどういう意味ですか」） | 話し始めて約 3 秒以内に先生が止まり、言い終わると先生がそれに答える。「止めた」が 1 増える | |
| D | イヤホンなしで 6 分話す | 先生が自分の声で止まり続けない。「止めた」が勝手に増え続けない | |
| E | イヤホンありで C を繰り返す | 毎回止まる（3 回中 3 回）。「エコー疑い」は 0 | |
| F | WeChat 内ブラウザで A〜C | 会話が止まって進めなくなる状態にならない | |
| G | エコーの疑いが続いたとき（D/F で起きうる） | 「半二重へ 1」「いま 半二重」になり、そのあと「半二重後の先生の発話」が増える＝会話が続く | |

## 本番 ON の判断基準（CEO 指示・2026-09-10）
Case C が 1 回成功しただけでは ON にしない。最低限すべて:
1. 明確な発話で割り込める（C・E）
2. 「あ」や咳で頻繁に止まらない（A・B）
3. イヤホンなしでも echo loop しない（D）
4. WeChat で会話不能にならない（F）
5. 異常時の fallback が実際に働く（G）

端末・ブラウザで結果が分かれる場合は、全員一律 ON ではなく環境別の rollout（例: イヤホン／通常ブラウザ → adaptive、WeChat×スピーカー → half_duplex）を検討する。
方針の切り替えは `src/lib/aiLesson/interruptionPolicy.ts` の `resolveInterruptionMode` だけで行える。

## 既知の不確かさ（実機で確かめること）
- **サーバーの自動割り込みが OFF にならない場合**: 会話開始時にクライアントから設定を変えている（`session.update`）。これが OpenAI に受け付けられていなければ、どの長さにしても「うん」で止まる。パネルで確認する。
  その場合の直し方は、会話トークンを発行する Edge Function（`ai-lesson-token`）側で最初から OFF にすること＝**本番の Edge Function の deploy が必要**（CEO 確認）。
- 先生の発話中は VAD の `create_response=false`。割り込みが成立したときだけ、生徒の発話が終わってから 0.8 秒待ってクライアントが `response.create` を送る。**C で「止まったのに先生が答えない」なら、ここを疑う**
- 閾値（`threshold 0.85`・止める長さ 2 秒）は仮の値。A/B で止まる・C で止まらない、が出たら調整する
- WeChat 内ブラウザで staging（pages.dev）が開けない・警告が出る場合がある
