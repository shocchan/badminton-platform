# Phase 1 — 既存教材のKnowledge Graph統合（2026-09-10）

**結論：新しいスキーマは作らなかった。既にあった構造を明文化し、機械が辿れる形にした。**

---

## 1. 正準Knowledge Item定義

### 文法の構造は、すでに4つの級で一致していた

N1・N2・N3・基礎（N5/N4）の4つのデータ源を比べたところ、**27フィールドが完全に一致**していた。
差分は5つだけで、どれも出典を記録するためのメタ情報（学習内容ではない）。

| | N1 | N2 | N3 | 基礎 |
|---|---|---|---|---|
| 共通の27フィールド | ○ | ○ | ○ | ○ |
| `sourceExample` / `zhSourceRowId` | × | ○ | × | × |
| `sourceRowId` | × | × | ○ | × |
| `matchKeys` | ○ | × | × | ○ |
| `reviewKey` | × | ○ | ○ | ○ |

**したがって正準Knowledge Itemは「新設計」ではなく「この27フィールド」。**

```
■ 同定
  grammarId, pattern, reading, level, unit, route

■ 正準知識（これが1つの知識の本体）
  meaningJa, explanationZh, formation, usageScene, nuance, register

■ 例と提示
  examplesJa, examplesZh, furigana

■ 学習者への手当て
  commonMistakesZh, learnerFocus

■ つながり（辺）
  similarPatterns, contrast, vocabularyLinks

■ 練習の派生（1つの知識から3形式が出る）
  recognition … 選択問題（選択肢・正解・誤答理由・中国語解説つき）
  production  … 産出プロンプト（expected / acceptable つき）
  practice    … AI会話ミッション（テーマ・切り出し・目標表現）

■ 品質管理
  reviewStatus, humanReviewed, approved
```

仕様 §4 の「10問の固定問題として保存するより、1つの正準知識＋複数の練習形式」は、
**文法では既に実現されている**。`recognition` / `production` / `practice` がその3形式にあたる。

### 語彙は別の形（統合しない）

語彙は `wordId, surface, reading, level, pos, glossZh, exampleJa, exampleZh,
collocationsJa, confusableSurfaces, explanationJa, explanationZh` で、文法とは別の形。
**無理に1つの型へ寄せない。** 学習の単位が違うものを同じ型にすると、どちらの都合も満たせなくなる。
共通なのは「IDで指せること」だけで、そこは下の ID 層が引き受ける。

## 2. Stable Knowledge ID

`src/lib/aiLesson/course/knowledge/knowledgeId.ts`

### 新しいIDを1つも作らなかった

学習履歴 `AdvMasteryLedger` は `Record<targetId, 試行[]>` で、**targetId がそのまま既存のID**。
新しいID体系へ振り直すと、実在学習者の攻略記録・復習予定・錯題本がすべて迷子になる。
だから**いま使われている文字列の読み方を定義しただけ**。

### 実在するIDの形

| 種類 | 形 | 件数 |
|---|---|---|
| 文法（番号式） | `n1g-001` `n2g-001` | N1 150 / N2 178 |
| 文法（綴り式） | `n3g-kke` `n5g-desu` | N3 76 / 基礎 148 |
| 語彙 | `vc-01-001` | 4,697 |
| 基礎語彙 | `fi-komaru` | 62 |
| 単元 | `n3u-01-self` `n5g-unit-1` | 12 ＋ 級ごと |
| 地域 | `area01-minato` | 10 |

番号式と綴り式の混在は**そろえない**。そろえた瞬間に学習履歴と切れる。

### 検証

本番の教材データそのものを通して確認済み（作り物のIDではない）。

- 文法 **404項目**が1つ残らず読める
- IDから読める級が、データの `level` と**全件一致**
- 基礎語彙62・N3単元12・地域10 も全件読める
- 知らない形（`grammar_n3_temoraou` など）は**解釈せず null**

## 3. 依存・関連の地図

`src/lib/aiLesson/course/knowledge/knowledgeGraph.ts`

### 問題：関連は書かれているのに、半分はIDになっていない

- `vocabularyLinks` → **すでにID**（`fi-komaru`）。機械が辿れる
- `similarPatterns` → **表示用の文字列**（「〜結果」「〜末に」）。辿れない
- `contrast` → 使い分けの説明文。人間向け

### やったこと：元データを1文字も変えずに解決する

`similarPatterns` は画面にそのまま出ている文字列でもある。IDへ置き換えると表示が壊れる。
**元データは表示のため、この層は機械のため**、と役割を分けた。

### 実測（417項目）

| | 値 |
|---|---|
| 関連の辺 | **608本** |
| 表示文字列の解決率 | **63%** |
| 語彙への辺 | **508本** |
| 孤立した項目 | **2件（0%）** |
| 未解決の表現 | 358件（ユニーク265） |

**未解決の265表現は欠陥ではなく、カリキュラムの穴の一覧そのもの。** Phase 2 の入力になる。
よく参照されるのに教材に無い表現の上位：

`〜ため`(6) `〜ています`(5) `〜など`(4) `〜から`(4) `〜はずだ`(4) `〜ている`(4)
`〜そうだ（伝聞）`(4) `〜につれて`(4) `〜と`(4) `〜ませんか`(4) `〜てもいいですか`(4)

初級の基本表現が多い。**N2/N3の項目が「〜ています」を関連として参照しているのに、
その項目が教材に無い**、という形の穴。

## 6. Coverage gap（Phase 2 で埋めるべきもの）

優先順に。**他級と同じ件数まで水増しするのではなく、穴を埋める**。

| 順 | 項目 | 現状 | 根拠 |
|---|---|---|---|
| 1 | **N1 聴解** | **0** | 他級は60〜100。N1学習者は模試の聴解が落ちる |
| 2 | **語彙の分野タグ** | **無し** | Practical Axis が存在しない |
| 3 | **未解決265表現** | 参照されるのに項目が無い | 関連・対比・推薦が痩せる |
| 4 | N1 語彙 | 317 | 他級 951〜1,562 |
| 5 | N1 読解 | 30 | 他級 80〜120 |

### Phase 2 で追加すべき教材量（提案）

**件数を目標にしない。** 埋めるべきは以下。

- **N1聴解**：まず模試1回分が成立する最小セット（他級と同じ構成なら30〜60）
- **分野タグ**：新規データではなく**既存4,759語への付与**。8分野（買い物・仕事・病院・役所・学校・交通・住居・人間関係）
- **未解決表現**：265のうち、**複数から参照されている上位（40前後）**を先に。全部は要らない
- **N1語彙・読解**：上の3つが終わってから。件数合わせで先に手を付けない

## 7. Migration pilot 結果

仕様の「N5 pilot」を**既存教材を正準構造へ載せる migration pilot** へ変更した結果：

**移行作業そのものが不要だった。** N5（基礎文法62項目）は既に27フィールドの構造を持っており、
ID層を足した時点で知識グラフに載った。データの書き換えは1件も発生していない。

これは N5 に限らず N1〜N2 まで同じ。**「載せ替え」ではなく「読み方を定義する」で済んだ**のが
Phase 1 の一番大きな成果。
