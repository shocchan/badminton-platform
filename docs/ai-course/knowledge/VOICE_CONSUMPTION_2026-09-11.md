# AI会話の回数: 会話が成立しなかった回は消費しない（2026-09-11）

CEO 指示: 「実質的なAI会話が成立していない session は回数を消費しない」。
0秒で打ち切られた会話でも回数券（¥300）が1枚減っていた問題を直す。

## 何が起きていたか
- 週3回の枠と回数券は、`ai_start_session` で**予約した瞬間**に1回ぶん減っていた。
- 接続前に閉じた回、前の回の自動打ち切り（`superseded-new`）、0秒の回も、会話ゼロのまま減る。
- QA アカウントでは 9/10 に回数券4枚のうち2枚が 0秒の `superseded-new` で消えた。

## Before / After
| 場面 | Before | After |
|---|---|---|
| 予約してマイク拒否・トークン取得失敗で戻った | 1回消費（券の回なら1枚） | 消費しない（回数の上限なし） |
| 前の回の自動打ち切り（`superseded-new`・接続前） | 1回消費 | 消費しない（前の回で会話が成立していれば、その回だけ消費） |
| 放置されて自動で閉じた回（`stale_timeout`） | 1回消費 | 会話が成立していなければ、下の段と同じ扱い |
| 画面の案内どおり「こんにちは」と言い、先生の最初の質問を聞いて閉じた | 1回消費 | 消費しない（直近7日で2回まで） |
| 接続直後に閉じた・数秒で中断・AI が応答しないまま終わった | 1回消費 | 消費しない（直近7日で2回まで） |
| つながらなかった（接続失敗・中国本土の回線など、トークンは出た） | 1回消費 | 消費しない（別枠で直近7日3回まで） |
| 先生の質問に答え、先生がまた返してから手動で終了 | 1回消費 | 1回消費（返さない） |
| 声を出していて、AI と90秒以上つながっていた（聞くだけ） | 1回消費 | 1回消費 |
| 成立したあと、終了理由を 0秒・中断に書き換えた | — | 1回消費（返らない） |
| 更新前の画面を開いたままの人が、つながって話した | 1回消費 | 1回消費（これまでどおり） |
| 回数券を引く時点 | 予約した瞬間 | 会話が成立した瞬間 |

## 「会話成立」の定義（コード上の1か所）
`supabase/migrations/20260911120000_ai_voice_session_consumption.sql` の `ai_voice_conversation_established`。

- ① 生徒が2回以上ちゃんと話し、先生が2回以上応答した
  （「こんにちは」→先生の最初の質問、だけでは成立しない。その質問に答えて先生がまた返したら成立）
- ② または、生徒が一度でも声を出していて、先生が話していて、90秒以上つながっていた

画面は数を数えて送るだけで、しきい値を持たない。「応答」は声の順番で数える（文字起こしの届く順番には頼らない）。

## 判定の段階
1. **AI の会話トークンが一度も発行されていない回は、必ず消費しない。** OpenAI の費用も発生していない。
2. **会話成立の報告が届いた回は、その時点で消費する。** 回数券の回はここで1枚引く。
3. **トークンは出たが、成立の報告が無いまま終わった回。**
   - 更新前の画面（材料を送らない版）から始めた回は、これまでどおり消費する。
   - 一度もつながらなかったと報告された回は、直近7日で3回まで消費しない。
   - つながったが会話にならなかった回は、直近7日で2回まで消費しない。
   - それを超えた回は消費する。

## 悪用防止
- 判定に使うのは、サーバーだけが書ける新しい台帳 `ai_voice_session_ledger`。
  生徒が書き換えられる `ai_learning_sessions` の列（秒数・終了理由・開始時刻・mode）は使わない。
- トークン発行は、Edge Function が OpenAI へ取りに行く**前に**台帳へ記録する。書けなければトークンを出さない。
- 報告を送らない・偽る改造クライアントでも、タダで話せるのは週5回まで（上の2回＋3回）。これまでは上限が無かった。
- つながっていた時間は、サーバーの時計（最初のトークン発行からの実時間）を上限に切る。
- 同じ回で回数券を2枚引かない（一意索引）。同時に2つのタブで始めても直列に処理する。
- ついでに塞いだ穴:
  - 開始時刻や mode を書き換えて週の枠を空ける（過去の回も含めて台帳で数える）
  - テキストで予約した回で音声のトークンを取る（音声で予約した回にしか出さない）
  - 終わった回を「進行中」に書き換えてトークンを取り直す（台帳の予約時刻で10分・1回の予約で5回まで）
  - 未ログインのまま他人の進行中セッションを閉じる（`ai_release_stale_sessions` の実行権限を外した）

## 回数券（¥300）への影響
- 購入と残高の台帳（`ai_conversation_credits`）の形は変えない。引く時点が「予約」から「会話成立」に移るだけ。
- 本番の回数券の行は、現時点で QA アカウントのものだけ（購入2行・付与1行・使用5行・利用者1人）。
- 過去に0秒で消えた券は、自動では返さない。返すかどうかは CEO 判断（QA アカウントは再付与で対応）。
- 成立の報告が遅れて届いたとき、残高が一時的に負になりうる。画面には0未満を出さない。
- 週の枠の回として予約した回でも、成立した時点で週の枠がもう埋まっていれば回数券の回として1枚引く
  （前の回を「終了して新しく始める」で閉じたあとに、その回の成立が遅れて届いた場合など）。残高が負になることがある。
- 別件（今回は直していない）: 券の回はサーバー上6分だが、画面は4分で会話を終える。

## 画面に出す残り回数
- 「今週あと何回」「あと何日で1回もどるか」は、消費した回だけで数える。
- 閉じずに離れた回（進行中のまま）は数えない。数えると入口が「使い切りました」になり、「前の回を終了して新しく始める」へ進めないため。
- 開始の判定では、閉じずに離れた音声の回があれば、回数の上限より先に「前の回を終了して新しく始める」を案内する。
  テキストの回が進行中のときは、これまでどおり上限を先に確かめる（始められない音声のためにテキストを終わらせない）。

## 本番へ出す順番
1. DB: この migration を流す（本番DBで begin〜rollback の試し流しをして、エラーが無いことと何も残らないことを確かめてから）。
2. 直後に、migration 内の「既存の音声セッションを台帳へ写す」insert をもう一度だけ流す（適用中に古い `ai_start_session` で作られた回を拾う。何度流しても同じ）。
3. すぐに Edge Function `ai-lesson-token` を出す（`./scripts/deploy-edge-functions.sh ai-lesson-token`）。
4. すぐに QA アカウントで1回トークンを取る（「台帳へ書く版が動き始めた時刻」が入る。これ以降の予約から「トークン無し＝必ず消費しない」が効く）。
5. 画面を staging → production の順に出す。

どの順番の途中でも、話し放題にはならない。
- 1 と 4 の間（トークンの記録がまだ無い間）は、トークン無しの回も「週2回まで見逃す」側で扱う。
- 3 と 5 の間（更新前の画面）は、トークンが出た回をこれまでどおり消費する。

## Rollback
1. DB: `supabase/migrations/20260911120000_ai_voice_session_consumption.rollback.sql` を流す。
   まだ決まっていない回を確定してから（トークンが出ていないと確かに言える回だけ消費しない。迷う回は 9/10 と同じく引く）、
   `ai_start_session` と `ai_my_conversation_budget` を 9/10 の本文へ戻す。
   「消費しない」と決まった回は、戻したあとも数え直さない。残高は0未満を出さない。台帳テーブルは残す。
   「台帳へ書く版が動き始めた時刻」は消す（あとで入れ直したとき、最初の記録からやり直すため）。
2. Edge Function: 戻さなくても動く。台帳の関数が無いときは従来どおりトークンを出す。
3. 画面: 戻さなくても動く。材料の送信が失敗しても会話は止めない。

⚠️ **DB をこの migration のままにして、Edge Function だけを古い版へ戻してはいけない。** トークンの記録が残らず、話した回が「トークン無し＝消費しない」になる。戻すなら DB を先に（または同時に）戻す。

## QA テストケース
### 自動（本物の Postgres・PGlite で migration をそのまま実行）
`src/lib/aiLesson/course/plans/voiceSessionConsumption.sql.test.ts`（60件）。架空の利用者だけを使う。
2回の敵対的レビュー（計18エージェント）で見つかった問題は、すべてこのテストに再現ケースとして入れてから直した。
- 会話成立の定義: 「こんにちは」と最初の質問だけは不成立／往復2回で成立／あいさつだけ／AI が応答しない／90秒の境目／AI が話していない／生徒の声が一度も届いていない／不正な値
- 予約しただけでは券が減らない
- トークン無し: 接続前に閉じた・マイク拒否をくり返す・発行失敗で戻した・放置で自動終了 → すべて消費しない
- 成立: 券は1枚だけ引く／手動終了でも返さない／0秒・中断へ書き換えても返さない／聞くだけ90秒は消費
- 報告なし: 2回まで消費しない・3回目から消費／報告を送らない改造クライアントでも上限まで／接続失敗は別枠3回／更新前の画面の回はこれまでどおり消費
- 遅れて届いた報告: 30分以内は消費へ直す／過ぎたら直さない
- 改ざん: 他人の回へ報告／接続時間の水増し／数を減らす報告／開始時刻・mode の書き換え／トークン無しの回への報告
- トークン発行: テキストの回／他人／本人が直接呼ぶ／10分超／6回目／消費しないと決まった回／材料を送る版の記録
- 週の上限と戻る日時／テキストは数えない／進行中の回／閉じずに離れた回の案内が上限より先／プランの合計
- 権限: 台帳に本人の権限が無い／内部の部品を呼べない／未ログインで開始できない
- 本番へ出す途中: 古い Edge Function の間も話し放題にならない／新しい Edge Function の最初の記録から「トークン無し＝消費しない」
- 既存の音声セッションを台帳へ写す: 回数券の行とつながる／書き換えても減らない／移る直前に予約した回もトークンを取れる
- rollback: 進行中の回を確定し、消費しないと決まった回を数え直さず、9/10 の動きに戻る

`src/lib/aiLesson/course/voiceEvidence.test.ts`（数え方）と `src/lib/aiLesson/course/plans/voiceTokenClaim.test.ts`（Edge Function と画面の約束）も同じ変更を守る。
