# 600円体験（実時間60分）と、間隔をあけた復習の食い違いをどうしたか

日付: 2026-08-26
決めた人: AI（実装判断）。価格・商品構成に触れる案は採らず、CEO判断を要さない範囲に留めた。

## 事実

`ai_start_trial` は受講権をこう書き換える:

```
valid_until = trial_started_at + trial_window_minutes   -- ai-trial-pass は 60
```

つまり **600円の体験は、始めてから60分の実時間で終わる**。同じ日のうちに切れる。

本番の唯一の体験購入者（2026-08-19）の実測:

| 項目 | 実測 |
|---|---|
| 体験の窓 | 16:20〜17:20 UTC（60分） |
| 会話セッション | 2回 |
| 実際に話した時間 | 398秒（6.6分） |
| 学習した表現 | 2個 |
| **復習の予定に入った表現** | **4個** |

60分のうち会話に使われたのは11%で、残りは初回設定・診断・画面の探索に消えている。
そして**復習の予定に入った4個は、この人には一度も届いていない**。翌日にはもう入れないから。

## 何がまずかったか

この商品の中心は「忘れかけた頃にもう一度出す」間隔反復で、復習は翌日以降に届く。
体験は同じ日に終わる。この2つは正面からぶつかっていたのに、
**両方を同時に約束する文言が3か所に出ていた**。

1. LP「AI体験パスでできること」→ 「翌日の復習が自動でつくられる」
2. レポート画面 → 「次の復習: 2026-08-27」（体験では絶対に来ない日付）
3. 利用上限のメッセージ → 「明日また続けましょう」

お金を払った人に、届かない約束を見せていた。

## 採らなかった案

**体験を「実時間60分」から「使った時間の合計60分（数日にまたがる）」に変える。**

学習設計としてはこちらが正しい。翌日の復習まで体験できるようになる。
採らなかった理由:

- 600円で何が買えるかが変わる＝**商品と価格の変更**であり、CEOの判断事項
- 既存の購入者1名の受講権の意味が後から変わる
- 「開始から60分」を前提にした実装（残り時間チップ、会話1回ぶんの残時間ガード、
  `PlanStatusChip` のリアルタイム表示）が全部前提を失う

したがって**提案として残す**。実装はしていない。

## 採った案

**言い方を実際の仕様に合わせる。** 商品も価格も体験時間も変えていない。

| 場所 | 前 | 後 |
|---|---|---|
| LP 体験の中身 | 翌日の復習が自動でつくられる | 間違えた表現が復習の予定に入る（届くのは続けたとき） |
| LP 注記 | （体験の長さを書いていない） | 体験は始めてから60分間です |
| レポート（体験中） | 次の復習: 2026-08-27 | この表現は日をおいてもう一度出てきます。体験は今日のうちだけなので、続けたときに届きます |
| レポート（月額） | 次の復習: 2026-08-27 | 明日、「〜」をもう一度練習します（翌日のときだけ言葉で） |
| 体験終了画面 | 値段3つの表 | 実データの「あなたの現在地」＋実際に予定されていた次の再会 |

体験中かどうかは受講権の `trial_window_minutes` で判定する（プラン名からの推測をしない）。

これで「4個が復習の予定に入っている」という事実が、
**届かない約束ではなく、続ける理由**として出るようになる。

## 残した宿題

- 体験を「使った時間の合計」に変えるか（CEO判断・価格の意味が変わる）
- 60分のうち会話が11%しかない問題そのもの。初回設定が体験時間を食わない設計は
  すでに入っているが、**開始後**の探索時間は食う。TTFVの実測を見て次を決める。
