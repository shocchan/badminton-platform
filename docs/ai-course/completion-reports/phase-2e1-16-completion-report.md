## 1. 練習は終わったのに結果画面へ進めていない状態からの復帰（§3・§4）

これまで判定関数はあったが**UIに接続されていなかった**ものを、学習者向けに接続した。

契約の進行記録に**総語数**を持たせ、`isTaskFinished()` で「最後まで終わったか」を判定できるようにした
（練習語数そのものは変えていない。記録するだけ）。

| 学習者に見えるもの | 内部で起きること |
|---|---|
| 「練習結果の保存を完了します。」 | — |
| 第一CTA「結果画面へ進む」 | 保存済みの回答から結果を作り、**契約完了だけ**を再試行 |
| 補助「いったんホームへ」 | 何も変更しない |
| 失敗時「練習は終わっていますが、結果画面を開けませんでした。」＋「もう一度試す」 | 成功を偽らない |

**学習も復習予定も再実行しない。** tokenが既に使われていた場合も、
completedTaskIds から完了を確認してJourneyのstepだけ進める。

### staging実機（sandbox内・E1）

| 確認項目 | 結果 |
|---|---|
| 「結果画面へ進む」を**2連打** | 契約 completed・completedTaskIds **1件**・token **1回だけ** |
| 復習予定 | **3件のまま**（重複生成なし） |
| Step4の表示 | 今日確認したことば3／正しく答えられた2／もう一度確認する1／覚えたと思う2／まだ少し不安1／3語が復習の予定に入りました |
| 結果の中身 | 保存済みの回答から再構成され、実際の内訳と一致 |
| 通常の学習記録 | 8,960文字のまま不変 |

練習が途中（総数に達していない）ときはこの復帰を出さない（テストで担保）。

## 2. schema Recovery の実機実証（§6・§7・§8）

sandbox内で3種類の状態を作って確認した。**通常キーは一度も操作していない。**

### F1 safely_migratable（v1契約をv2 clientで開く）
Recovery画面を出さず、そのまま学習を続けられた。
journeyId・activeTaskId・completedTaskIds をすべて保持。通常の学習記録も不変。

### F2 incompatible（自動移行できない古い版）
「学習の続き方を確認できませんでした／この初回学習だけ最初から始められます。
ことばの学習記録と復習の予定は消えません。」を表示。
自動完了せず、render crashも無く、sandbox内の学習記録と復習予定（1件）も保持。

**この検証で第一CTAが「ホームへ」になっている不具合を発見**（指示は「最初から始める」が第一CTA）。
修正して再確認済み。

### F3 corrupted（壊れたJSON）
同じRecovery画面。Error Boundaryへ落ちない。stack traceは出さず、
技術詳細は labPreview の折りたたみ（developer detail）内のみ。
第一CTAを押すと契約キーだけが消えてStep1から再開でき、**ループしない**。
sandbox内の学習記録と復習予定は保持された。

### F4 newer_than_client
分類・Recovery表示・自動再読込の回数制限は実装済みでユニットテストで担保。
**実機での再現は未実施**（保存版を人為的に未来の版にする操作が必要で、
今回はF1〜F3を優先した）。
