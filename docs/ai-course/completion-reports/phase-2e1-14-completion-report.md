## 3. 検証用サンドボックスの学習者向け接続（§7）

`courseStorageRegistry.ts` に `isJourneySandboxActive` / `beginJourneySandbox` を追加し、
ことば図鑑の内部入口に「初回学習を安全に試す（通常の記録に影響しません）」を置いた。

- 動作中は通常キーを**一切読まず・書かず**、sandbox名前空間だけを使う
- 判定は sandboxキーの存在そのもの。**新しいキーを増やさず**、再読込をまたいでも続く
- 終了時は sandboxキーのみ削除（`safeResetKeys` の allowlist 経由）
- 動作中は常にバナーを表示し、いつでも終了できる

**実機で確認**: sandbox開始・Journey完走・終了のすべてを通して、
CEO端末の学習記録（8,960文字）・復習予定（319文字）・Journey完了日時が**一度も変化しなかった**。
これで今後の検証で通常キーを退避・削除する必要がなくなった（R9の再発を構造的に不可能にする最後の一手）。

## 4. 再開位置（§3・§4）

契約schemaを **v2** にし、確定した操作だけを再開位置として持つようにした（v1も読める）。

| 保存するタイミング | 保存しないタイミング |
|---|---|
| card完了・正誤確定後の「次へ」・次の語へ | **選択しただけ**（未確定） |
| 診断の回答確定（出題セットごと） | 選択しただけ |
| — | 契約が完了済みのとき（位置を動かさない） |

診断は出題セットが学習記録から作られるため、回答が増えたあとに作り直すと別の問題になる。
そこで**確定時点のセットそのもの**を保存し、同じ問題の続きから再開する。

## 5. 部分成功Recovery（§5）

`journeyRecovery.ts` に副作用のない決定的関数 `planJourneyRepair` を追加。
保存済みの事実だけから修復計画を決める（URLやrouteでは判断しない）。

| 状態 | 判定 | 行うこと |
|---|---|---|
| 契約completed・stepが前 | `step_behind` | **stepだけ**修復。tokenもcompletedTaskIdsも触らない |
| 契約completed・画面だけ前 | `view_behind` | 表示するだけ。完了処理を再実行しない |
| 契約completed・結果が無い | `snapshot_missing` | 欠損として扱う（**0と断定しない**） |
| 学習済み・契約未完了 | `contract_pending` | 契約完了だけ再試行。**学習はやり直させない** |
| Journey完了済み | `none` | 触れない |

`resolveSnapshot` は「保存済み → 再導出（partial扱い）→ 全項目null」の順で決め、
**推測で数値を作らない**。

## 6. staging実機で確認したこと

- 通常の学習記録は最後まで 8,960 文字のまま

## 7. アクセシビリティ（§11）

`LearningIllustrations.tsx` を監査し、**イラストは既定で装飾**（`aria-hidden` ＋ `focusable="false"`）に変更。
隣に必ず同じ意味の見出しがあるため、`role="img"` + ラベルは重複読み上げになっていた。
隣接テキストが無い場所で使う場合だけ `label` を渡すと意味のある画像として読まれる。

横棒グラフ・復習タイムラインは、図形要素を `aria-hidden` にし、**件数と予定はテキストを主情報**にしている
（監督の指摘どおり、図を読み上げさせるより隣接テキストを読ませる方が適切）。

## 8. モバイル・200% zoom（§12・§13）

| 幅 | 横overflow | 44px未満の操作 |
|---|---|---|
| 320×568 | 0 | 0 |
| 375×667 | 0 | 0 |
| 390×844 | 0 | 0 |
| 430×932 | 0 | 0 |
| 768×1024 | 0 | 0 |
| **188×500（375pxの200%zoom相当）** | **0** | 5 |

途中で**自分が入れた修正が横スクロールを作っていた**ことを実測で検出した。
2E-1.13でタップ領域を広げるために付けた `min-w-11` が、5タブ合計で幅を強制し、
188pxで48pxの横あふれを起こしていた。均等割り（`basis-0` + `min-w-0`）へ変更して解消。

**未達を正直に記載**: 188px幅では主要操作が44px未満になる（5タブで幅が足りない）。
横スクロールを作るよりは良い、という判断。contrast の自動計測は外部サービスなしでは行えず**未確認**。
