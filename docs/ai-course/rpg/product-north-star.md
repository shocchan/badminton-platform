# North Star: 主人公冒険型・日本語攻略RPG

作成: 2026-07-28（CEO最上位方針として確定） ／ **本ファイルが全設計判断の最終基準**

## 一文で言うと

**利用者が主人公となり、日本語を学ぶことで世界の霧が晴れ、行ける場所・会える人・
読める文字・分かる物語が増えていくオリジナルRPG。**

## 「教材が多いこと」は価値ではない

最終価値は次の一点に集約する。

> 昨日できなかったことが今日できるようになり、**その成長によって世界が実際に広がる**。

数字が増えるだけの設計、教材一覧を並べるだけの設計は、この基準に照らして不合格とする。

## 判断の優先順位（迷ったらこの順）

1. **学習として正しいか**（間違った日本語・偽の達成感は演出より優先して排除する）
2. **主人公が前に進んだ実感があるか**（世界・人物・物語が実際に変化したか）
3. **成人が使って恥ずかしくないか**（幼児的でない・落ち着いた上質さ）
4. **迷わず操作できるか**
5. **見た目の魅力**

## 三層アーキテクチャ（RPG化で学習エンジンを作り直さない）

```
┌─────────────────────────────────────────────┐
│ Narrative / World / Adventure Presentation Layer │ ← 新規（RPG）
│  世界地図・章・クエスト・人物・物語・冒険値・報酬演出      │
├─────────────────────────────────────────────┤
│ Learning Domain Layer                        │ ← 既存（変更しない）
│  Vocabulary/Grammar Item・Sense/Usage・診断・問題・     │
│  会話練習・間隔反復・攻略ルート・Unit・XP・Recovery      │
├─────────────────────────────────────────────┤
│ Persistence / Sync Layer                     │ ← 既存（設計済み）
└─────────────────────────────────────────────┘
```

**依存の向きは上から下の一方向のみ。** 学習ロジックがRPG層を参照してはならない。
RPGを外しても学習が成立し、学習ロジックを差し替えてもRPG層が壊れない構造を保つ。

## 絶対にやらないこと

- 既存ゲーム作品・キャラクター・名称・画面・物語・モンスター・アイテム・効果音・ロゴの模倣
- 簡単な問題の反復で日本語能力が上がったように見せること
- 演出のために正誤判定・復習間隔・習得判定を歪めること
- ガチャ・課金抽選・pay to win
- 法務承認前の現実景品付与・抽選
- 幼児向けの絵柄・語り口（対象は成人の中国語母語者）

## 用語の分離（混同禁止）

| 概念 | 何を表すか | 上げ方 |
|---|---|---|
| **冒険値（Adventure XP）** | 続けた・挑戦した・完了した量 | 学習行動そのもの |
| **冒険者ランク** | 冒険値の累積段階 | 冒険値で自動 |
| **ことばの力（Mastery）** | 実際に使える日本語 | 自力正解・別日再現・別文脈使用・会話での使用 |
| **JLPTレベル** | 外部試験の目安 | 教材のlevel属性（N5〜N2）。冒険者ランクとは無関係 |

詳細は [xp-and-mastery-separation.md](xp-and-mastery-separation.md)。

## Vertical Slice ファースト

全世界を一度に作らない。**Chapter 1「はじまりの港町」だけを完全に遊べる形**で作り、
「学習として成立する／先が気になる／子どもっぽくない／迷わない／世界観と教材が分離していない」
の5点を確認してから展開する。計画は [chapter-1-vertical-slice-plan.md](chapter-1-vertical-slice-plan.md)。

## CEO追加指示（2026-07-28・正式）: 見下ろし型ドットRPGの空気感

参考にするのは**GBA時代の見下ろし型ドットRPGの「懐かしく温かい空気感」だけ**。
俯瞰マップのワクワク感、「町→道→施設→人との出会い」という体験構造を参照する。

1. **既存作品の直接模倣は禁止。** 既存IPのキャラ・マップ・UI・モンスター・ロゴ・配色・画面構成の丸写しをしない。世界・人物・町・導線・UIはすべてオリジナル。
2. **細かいゲーム操作は入れない。** 十字キー移動・自由歩行・アクション操作・リアルタイム戦闘は主要設計に含めない。**学習を進めることで冒険が進む**（学習の進捗＝物語の進行、正しい理解＝霧が晴れる、復習＝過去の場所との再会）。
3. **体験の基本は「学習すると進むRPG」。** 単元・会話練習の完了で次の場所・会話・看板・イベント・人物が開く。章末は10問テストではなく**場面攻略**（駅で聞く・店で頼む・職場で相談する）で締め、攻略後は必ず物語上の変化（関係・行ける場所・読めるもの・次の依頼）が起こる。
4. **ビジュアル方向。** ドットRPG風見下ろしマップを感じさせる温かい色味の世界（町・道・草木・建物・看板・NPC）。ただし実装はWebアプリとして軽く、情報設計の分かりやすさ優先。完全なゲーム画面ではなく**「RPG風の学習UI」**。learner導線は「どこを押せば進むか一目で分かる」こと。
5. **設計ルール。** 以後のUI・マップ・クエスト・エリア・イラスト・進行導線はこの方向性と矛盾させない。ただし**教材本体と学習導線の完成が先**で、RPG演出はその上に積む。「雰囲気だけRPG」で終わらせず、**学習の進行と物語の進行が構造として一致**することを最優先とする。
