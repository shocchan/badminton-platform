## P0 一覧（誤った知識を覚える／正解が存在しない／複数正解 → 即修正）

### 読解 P0（1件）

#### R-P0-1 `n2r-info-02`（引越しサービス 料金表 / infoSearch）
**誤答2つの `whyWrongJa` が算数として成立していない。学習者が誤った計算ルールを覚える。**

本文のルール: 基本料金 30,000円（10km以内）／追加距離 10kmごとに +3,000円／作業員追加1名 +8,000円／土日祝は**基本料金の**20%増。
正解は 30,000 + 6,000 + 8,000 = **44,000円**（これは正しい）。

- 誤答 `41,000円` の `whyWrongJa`「**作業員追加が入っていません。**」→ **事実と違う**。
  41,000 − 30,000 − 8,000 = 3,000 なので、作業員追加 8,000円は**入っている**。実際は「追加距離を1回分（+3,000円）しか数えていない」金額。
  作業員抜きなら 36,000円であって 41,000円にはならない。
- 誤答 `52,800円` の `whyWrongJa`「**土日祝の割増を入れた金額です。**」→ **本文のルールで再現できない数字**。
  本文は「土日祝：**基本料金の**20%増」なので、正しくは 30,000×1.2 + 6,000 + 8,000 = **50,000円**。
  52,800 は 44,000×1.2、つまり**合計額全体に20%を掛けた**もので、本文の規定と矛盾する。
  土日祝の計算を練習した学習者は 50,000円を出し、「教材が 52,800 と言っている」ことで**誤ったルールを刷り込まれる**。

**どう直すべきか**
- `41,000円` の理由を「追加距離を1回分しか計算していません（25kmは2回分）」に差し替える
- `52,800円` を `50,000円` に差し替える（本文ルールと整合させる）。もしくは選択肢を撤去して別の誤答（例: 36,000円「作業員追加が入っていません」）に置き換える
- 併せて `questionZh`「平日搬到25公里外…」の `平日` は中国語では「ふだん・平素」の意味で、**weekday の意味にならない**。`工作日` に直す（この設問は「平日 vs 土日祝」が誤答の分岐点なので影響が大きい）

補足: 対応する本番データは `src/lib/aiLesson/course/adventure/reading/n2ReadingSets.ts:285-293`。パイロットサンプルは本番TSの忠実な抽出であることを確認済み。

### 聴解 P0（5件）

#### L-P0-1 `n3l-int-19`（歓迎会の店 / integrated）— **音声上、正解が2つになる**
原稿:「たけのは駅から歩いて**十分**で、個室があり、魚と野菜の料理が中心です。」
→ TTSは **「じゅうぶん」** と読む（MD5一致で実証）。

会話の3条件は「魚と野菜」「個室あり」「駅から**五分以内**」。
たけのを除外できるのは距離条件だけだが、音声では「じゅうぶん」としか聞こえず**数値情報が消える**ため、
たけの（個室◯・魚野菜◯）と ほしの（正解）が**どちらも条件を満たすように聞こえる** → 複数正解。

**どう直すべきか**: `十分` → `１０分` または `じっぷん` と表記する（原稿の表記を変えるだけで音声が直る）。

#### L-P0-2 `n3l-int-08`（不動産屋 部屋選び / integrated）— **音声上、正解が2つになる**
原稿に `十分` が4回登場する（三号室・四号室の徒歩時間、女「駅から**十分**より遠いと」、男「歩いて**十分**までだね」）。
すべて「じゅうぶん」と読まれ、**距離条件が丸ごと機能しなくなる**。

残る条件は「家賃8万円まで」「猫が飼える」の2つだけ。すると
二号室（6万円・猫◯・徒歩15分）と 四号室（正解: 7万5千円・猫◯）の**両方が正解になる**。

**どう直すべきか**: 4箇所すべて `１０分` / `じっぷん` に。徒歩15分は `十五分` のままで正しく読まれる。

#### L-P0-3 `n3l-int-03`（発表の相談 / integrated）— **誤った日本語知識を刷り込む**
原稿の冒頭: 先生「**発表は十分です。**」
→ TTSは「はっぴょうは**じゅうぶん**です」と読む（MD5一致で実証）。学習者の耳には
**「発表はそれで足りています／もう十分です」**という**まったく別の意味**として届く。

- 「発表10分」という設問の中核情報が**音声に一切存在しない**
- 正解選択肢のテキストは `発表十分、質問五分、資料は五枚まで`。学習者は「じゅうぶん」と聞いた音と、この「十分」という文字を結びつけてしまう
- 解答後に表示される原稿（`AdvListeningRunner.tsx:186`）にも `発表は十分です` と出るため、**誤読が定着する**

（正誤自体は「資料5枚」「質問5分」で消去法的に決まるため、正解は一意ではある。しかし誤った読みを教える点でP0と判断した。）

**どう直すべきか**: `発表は１０分です` もしくは `発表は十分（じっぷん）です`。加えて選択肢テキストの `発表十分` も `発表10分` に統一する。

#### L-P0-4 `n3l-quick-02`（即時応答 / quickResponse）— **複数正解、かつ誤答理由が誤り**
読み上げ:「その資料、もう送っていただけましたか。」
- 正解 a: 「すみません、まだなんです。」
- 誤答 c: 「**いいえ、送りましょうか。**」`whyWrongJa` =「質問への答えになっていません。」

c の「いいえ」は**まさに質問への答え**（＝まだ送っていない）であり、その後の「送りましょうか」は自然な申し出。
日本語として完全に成立する応答で、**a と同等かそれ以上に自然**。即時応答として正解が2つある。
さらに `whyWrongJa` の記述自体が事実と異なり、学習者に誤った判断基準を教える。

**どう直すべきか**: c を役割が明確に破綻する選択肢に差し替える（例:「いいえ、まだ届いていません」＝受け取る側の言い方）。

#### L-P0-5 `n3l-point-11`（犬の散歩 / pointComprehension）— **複数正解（設問文の不備）**
原稿: 男「昼は暑いですし、人も多いですからね。」女「**それもあるんですが**、人は平気なんです。（…工事の音で立ち止まる…）」

設問は `女の人はどうして犬の散歩を夜にしているのですか。`（**「一番の」がない**）。
女性は「それもあるんですが」と**暑さを理由の一つとして明示的に認めている**ため、
誤答 b「昼は気温が高くて暑いから」も**本文に根拠がある正しい理由**になってしまう。

`whyWrongJa` 自身が「**一番の**理由ではありません」と書いており、**設問文と噛み合っていない**（設問は一番の理由を聞いていない）。

**どう直すべきか**: 設問を `女の人が犬の散歩を夜にしている一番の理由は何ですか。` に変更する（同ファイルの `n3l-point-02` は「一番の理由は何ですか」と正しく限定しており、そちらに揃えればよい）。

### 読解 P1（1件）

#### R-P1-1 `n3r-info-02`（日本語教室のご案内 / infoSearch）— 中国語の設問文が条件を伝えられない
`questionZh`: 「**平日**晚上要工作、只有周六有时间的初级学习者该怎么办？」

中国語の `平日` は「ふだん・平素・いつも」の意味で、**日本語の「平日＝weekday」にはならない**。
この設問は「平日夜は不可／土曜のみ可」が答えの分岐点そのものなので、
中国語だけを頼りに読むと**条件設定を取り違える**。`工作日` が正しい。

同じ「、」の使い方も日本語の読点で、中国語では並列の名詞以外に頓号は使わない（`平日晚上要工作，只有周六…` が正しい）。

### 聴解 P1（6件）

#### L-P1-1 `n2l-point-13`（車を手放す / pointComprehension）— 音声が非文になる
原稿:「気がついたら歩くのが**十分**もない日が続いてて」→「じゅうぶんもない」と読まれ、**日本語として成立しない音**になる。
（正解 a の根拠は「隣の通りに何ができたのかも知らない」でも取れるため、正解自体は崩れない。）

さらに `explanationZh` にこの `歩くのが十分もない` がそのまま日本語で引用されている。
**中国語の「十分」は「非常に」の意味**なので、中国語話者は「歩くのが非常に…ない」と読む。二重に誤解する。

**どう直すべきか**: `歩くのが１０分もない日` に。`explanationZh` の引用も同様に。

#### L-P1-2 `n2l-outline-14`（観光地の混雑 / outlineComprehension）— 前提が別の意味になる
原稿:「数えてみると、**一日**の来訪者はそれほど多くありません。」
→ TTSは **「ついたち」** と読む（MD5一致で実証）。
「一日あたりの来訪者数は多くない」という**話の前提**が、「**1日（月の初日）の**来訪者は多くない」に変わる。

**どう直すべきか**: `一日` → `１日あたり` もしくは `いちにちの来訪者`。

#### L-P1-3 `n2l-task-02`（レポートのテーマ / taskComprehension）— 音声が二重に壊れている
1. 原稿:「テーマは、**一行**でいいので今週中に。」→ TTSは **「いっこう」** と読む（MD5一致で実証）。「一向」に聞こえ、文が意味不明になる。
2. `toSpeech()` の話者記号除去（`generate-listening-audio.mjs:24-31`）が `教員「` にマッチしないため、
   実際の読み上げテキストはこうなる（実測）:

   > `…教員「レポート、提出は来週でいいですが、テーマだけは今週中に出してください。はい。参考文献のリストも一緒でしょうか。教員「それは本文と一緒で構いません。…`

   `学生「` は除去され、`教員「` は**そのまま音声化される**。結果、**学生の発話が教員の文にそのまま続いてしまい、誰が話しているのか分からない**。

**どう直すべきか**: `一行` → `一文` または `１行`。加えて `toSpeech()` の話者パターンに `教員|担当|課長|先輩|後輩|相談員` を追加する。

#### L-P1-4 `n2l-task-18` / `n2l-task-11` — 話者記号の除去が片方だけ効き、非対称な手掛かりになる
`toSpeech()` を実際に適用した結果（実測）:

- `n2l-task-18`: `女「` は除去、`担当「` は**読み上げられる** →「たんとう」だけがアナウンスされる
- `n2l-task-11`: `女「` は除去、`課長「` は**読み上げられる** →「かちょう」だけがアナウンスされる

どちらも設問が「女の人はこのあとまず何をしますか」「課長はこのあとまず何をしますか」と**話者を特定して問う**形式であるにもかかわらず、
**片方の話者にだけ音声ラベルが付く**。意図しない手掛かりであり、かつ他セットとの難易度が揃わない。

**どう直すべきか**: L-P1-3 と同じ正規表現の修正。全セットで統一的に除去する（または全セットで統一的に残す）。

#### L-P1-5 【横断】全対話セットに話者交代の音響的手掛かりがない
`generate-listening-audio.mjs` は `VOICE = 'Kyoko'` の**1音声のみ**で全セットを生成し、
`toSpeech()` は `男「` `女「` を **句点（。）に置換**する。
つまり、二人の会話が**同一女性話者の連続した独白**として読み上げられ、話者交代は通常の文末と区別がつかない。

影響する設問（話者を特定して問うもの）:
`n3l-point-18` `n3l-point-09` `n3l-point-11` `n3l-point-19` `n2l-point-18` `n2l-point-13` `n2l-point-09`
（+ 統合理解の対話部分 `n3l-int-19` `n3l-int-18` `n3l-int-08` `n2l-int-17` `n2l-int-13` `n2l-int-16` `n2l-int-14`）

多くは「質問 → 回答」の内容構造から誰の発話か推測できるため即・不正解にはならないが、
**JLPT聴解の中核スキル（話者の識別）が訓練できない**。有料提供の前に方針を決めるべき箇所。

**どう直すべきか**: 話者ごとに別ボイスを割り当てる（macOS内蔵なら `Kyoko` / `Otoya` の2音声）。
それが難しければ、最低限、話者交代位置に明確な無音ポーズを挿入する。

#### L-P1-6 `n3l-int-03` — 中国語3フィールドで `发表` が通じない
- `situationZh`: 「老师和学生在谈**发表**。」
- `questionZh`: 「关于**发表**，正确的是哪一个？」
- `explanationZh`: 「要综合三个信息（**发表**10分钟・资料最多5页・提问5分钟）。」

「在谈发表」は中国語として意味を成さない。**音声を聞く前の状況説明がこれなので影響が大きい**。

**どう直すべきか**: `发表` → `课堂报告` / `口头报告` / `演讲`。
併せて `explanationZh` の中黒 `・` は日本語の記号なので中国語では `、` に。

   選択肢は実行時にシャッフルされるが（`advChoiceOrder.ts`）、長さの偏りはシャッフルでは消えない。

2. `n2l-int-17`（社宅の部屋）— **`一階` と `一回` が完全に同一音声**（MD5一致で実証）。
   同じ原稿内で「一つ目は**一階**の部屋」「乗り換えが**一回**あり」「**一階**は人の通りが気になります」と
   両方が絞り込み条件として登場する。文脈で復元は可能だが、N2でも負荷が高い。

3. **選択肢だけで解けてしまう** — `n3l-outline-04`（正解19字 / 誤答「昼ごはんの値段」7字・「部署を変えたい」・「会社をやめたい」）、
   `n3l-outline-11`、`n3l-outline-14`、`n2l-outline-09`。
   正解がもっともらしい一般論で、誤答が明らかに的外れ。音声を聞かずに選べる。

4. `n3l-point-19`（打ち合わせの場所）— 設問に「一番の」がなく、
   誤答 d「店ではお茶が出るから」に対し原稿は「それは**ついで**ですね」と述べている。
   L-P0-5 ほど明確ではないが（「ついで」は理由の否定に近い）、同じ構造。設問に「一番の」を足すのが安全。

5. `n2l-quick-12`（会計）— 読み上げ「こちらの**合計の数**ですが、少し違っているように思うのですが。」
   会計の場面で「合計の数（かず）」は不自然（正しくは「合計の**金額**」「合計」）。
   その不自然さに引きずられて誤答 b「ええ、数が多いほうがいいですね」も日本語として成立しておらず、誤答として機能していない。

6. **N3 統合理解の情報量が過大** — `n3l-int-19` `n3l-int-18` `n3l-int-08` はいずれも
   **4選択肢 × 3条件 = 12項目**を音声のみで保持させる。実際のJLPTでN3にこの形式はない（統合理解はN1のみ）。
   `playLimit: 2` で緩和されてはいるが、N3学習者には負荷が高い。

7. **`whyWrongJa` が日本語のみ** — `AdvListeningRunner.tsx:191` / 読解側も同様で、
   誤答理由は中国語版が用意されていない。N3学習者には解説が読めない可能性がある。

## P3（好みの範囲）

**件数: 8件**

1. **中国語文中に日本語の記号** — 全角 `＝` が6箇所（`n3r-info-01` `n2r-info-02` `n3l-point-04` `n2l-outline-17` `n2l-point-18` `n2l-point-04`）、
   中黒 `・` が1箇所（`n3l-int-03`）。中国語では使わない。
2. **中国語文中に日本式の読点 `、`** — 5箇所（`n3r-info-10` `n3r-info-12` `n3r-info-15` `n3r-info-02` `n2r-info-23`）。並列以外は `，`。
3. **`男人` / `女人`** — 聴解の `situationZh` / `questionZh` で多用。中国語のJLPT教材では `男的` / `女的` / `男士` / `女士` が一般的。
   同一ファイル内でも `n2l-int-17` は `女士`、`n2l-outline-14` は `女人` と揺れている。
   `n3l-outline-10` の「**种地的女人**」はやや粗い（`务农的女性`）。`n2l-task-17` の `后辈` も中国語では通じにくい。
4. **`situationJa` の書式不統一** — `n3l-quick-06`「友だちに手伝いを頼まれます。**返事を選びます。**」に対し
   `n3l-quick-16`「店の人に声をかけられます。」（後半なし）。中国語側は両方とも「选择合适的回答」がある。
5. **`playLimit` の不統一** — 即時応答（quickResponse）8セットのうち `n3l-quick-02` `n3l-quick-16`… を含め
   `n3l-quick-02` だけ `playLimit: 2`、他は 1。実際のJLPT即時応答は1回のみ。
6. **`rationaleSpan` が正解根拠の一部しかカバーしない** — `n3r-info-10`（料金の根拠が含まれない）、
   `n3r-info-01`（水泳帽100円が含まれない）、`n2r-int-23`（Ａ側の根拠が含まれない）。
   本文には実在するので誤りではないが、「根拠のハイライト」としては不完全。
7. **`【A】【B】` の全角・半角不統一** — `n2r-int-06` のみ半角 `【A】`、他の統合理解3セットは全角 `【Ａ】`。
8. **JSON上の正解位置が `choice-a` に極端に偏っている** — `reading-N3` 18/20、`listening-N3` 17/20、
   `reading-N2` 15/20、`listening-N2` 13/20（全体で 63/80 = 79%）。
   **実行時に `advChoiceOrder.presentQuestion()` で決定的シャッフルされるため学習者への影響はない**
   （`answer-distribution.json` でも4位置が各25.0%、χ²=0.02）。
   ただしデータを目視レビューする側が誤解しやすく、シャッフルが将来外れた場合の事故リスクになる。

## 検証方法の記録（再現手順）

TTSの読み方は以下の方法で実証した（推測ではない）。

```bash
say -v Kyoko -r 175 -o a.aiff "発表は十分です"
say -v Kyoko -r 175 -o b.aiff "発表はじゅうぶんです"
say -v Kyoko -r 175 -o c.aiff "発表はじゅっぷんです"
md5 -q a.aiff b.aiff c.aiff
# a と b が完全一致 → Kyoko は「十分」を「じゅうぶん」と読む
```

同じ手法で `一日→ついたち`、`一行→いっこう`、`一階＝一回` を確認。
逆に `三分` `五分` `十五分` `三十分` `三分の一` `七割` `三名` `八百屋` `合計の数` は正しく読まれることも確認済み。

話者記号の除去漏れは、`toSpeech()` を Node で再実装し全40セットに適用して検出した。
