## A. 成長タブ（Can-do / Before-After / できるようになったこと）

### いまどうなっているか

| 部品 | 実装 | V2の生徒に届くか |
|---|---|---|
| `courseCanDo.CAN_DO_BY_CATEGORY` | あり（12カテゴリ・日中） | ✕ |
| `CanDoAchievementCard` | あり | ✕ |
| `BeforeAfterSpeechCard` / `courseBeforeAfter` | あり | ✕ |
| `SpeakingSkillSummary` / `GrowthSnapshotCard` | あり | ✕ |
| `GrowthOverview`（上をまとめた画面） | あり | ✕ |

理由は1行だけ。`CourseHeader.navItems(showLab, v2Mode=true)` が
**home / roadmap / settings の3つしか返さない**ので、`growth` へ入る道が画面に無い。
`goNav('growth')` の実装自体はV2でも動く。

いまV2の生徒に出ている「成長」は、週まとめの4段階（今日・今週・30日・半年）で、
中身は **学習日数・やりきった冒険・合格した挑戦・解いた問題数**——つまり数と回数だけ。

### 提案：**ナビを増やさず、週まとめの一番上にCan-doを1枚置く**

ナビ項目を4つにするのは、いまのフェーズと競合するし、canon 原則3（主要CTAは常に一つ）とも
相性が悪い。既にある「週のまとめ」（`view === 'weekly'`）の**先頭**に置く。

```
週のまとめ
├─ ① できるようになったこと      ← 新規（このカードだけ足す）
├─ ② 成長の4段階（今日/今週/30日/半年）   ← 既存
├─ ③ 技能別の変化                ← 既存
└─ ④ 来週の重点                  ← 既存
```

### ①の中身（3つの出どころを1枚に混ぜる）

| 出どころ | 言い方 | 根拠 |
|---|---|---|
| AI会話（旧エンジンの `ItemProgress`） | 「丁寧に休暇の相談ができる」 | `CAN_DO_BY_CATEGORY[category]` ＋ `isAchieved`（自力使用以上） |
| 試験ルート（mastery台帳） | 「N3の『〜てある』を、別の日に3回・7割以上で通した」 | `masteredTargetIds` ＋ 束の `pattern` |
| 会話の言い直し | 「『〜ていただけますか』を自分で言い直せた」 | `restateLog` の `said === true` |

**新しいデータは1つも作らない。** 全部いまある記録の言い換え。

### 守ること（原則13）

- 会話を1回もしていない生徒には会話由来のCan-doを出さない（空欄も出さない）
- 「合格できる」「マスターした」は書かない。**測った事実の言い換えだけ**にする
- 1枚に出すのは**最大3件**（canon §7 の「最大3件」と揃える）。多いと読まれない
- 0件のときはカードごと出さない。「まだありません」は成長画面には要らない

## B. ミナモ列島（章1〜10・約1,400行）

### なぜ gate があるのか（調べた結果）

`!advOn` は「V2には物語を出さない」という好みの問題ではなかった。**3つの実体的な理由**がある。

1. **章はブロッキングのゲートだった。**
   `openArea` は施設（塔・港・庭園）へ入る前に導入章を必ず通していた。
   2026-08-17 の監査（commit 1367ff7）で「P1 旧コース到達経路の封鎖」として無効化された。
   canon 原則16（探さないと学習できない設計にしない）に反していた。

2. **章の進行はサンドボックスのlocalStorageにしか保存されない。**
   `adventureState.ts` の冒頭にそう書いてある——
   `RPG_SANDBOX_KEY = 'kawabado.aiCourse.v1.rpgLabSandbox'`、
   「保存先は sandbox 専用キーのみ。通常learner系キーには一切触れない」。
   **端末を変えたら章の進みは消える。** DBに1バイトも残らない。
   V2の学習記録（DBのjsonb）と耐久性が違うものを同じ画面に並べると、
   「進めたのに消えた」が起きる。これは今回Cで外した旧SRSとまったく同じ問題。

3. **章の完了条件が旧モデルの教材に紐づいている。**
   各Questの `learningItemIds` は `foundationVocabBank`（基礎140語）の実在ID。
   N2/N3を目指すV2の生徒のルートにはこの単元が無いので、
   そのまま開くと「章を進めるために、自分のルートに無い教材をやらされる」ことになる。

### 未完成ではない部分

- 章データそのものは10章ぶん完成していて、`chapterRegistry.test.ts` が
  「実在教材IDだけを参照していること」を機械検証している
- 画面は `lazy()` で読み込まれるので、**いま出していない生徒のバンドルには入っていない**
  （＝開けていないことによる性能上の損はない）
- モバイルは 390×844 で過去に実測済み（`Chapter1AdventurePanel` は既存の実機チェック対象）

### 提案：**進行を保存しない「読み物」として、攻略の直後にだけ1枚出す**

3つの理由のうち、いちばん重いのは②（保存が消える）。
なので**保存が要らない形**に落とす。ゲートにもしない。

```
stageを攻略した直後（advCelebration が祝いを出す瞬間）
  → そのエリアの章の「opening scene」1枚を、祝いのあとに1画面だけ出す
  → 読んだら「今日の冒険へ」。既読フラグも進行も保存しない
```

- **ゲートではない**（攻略の報酬として出るだけ。押さなくても学習は進む）
- **保存が要らない**（1枚読むだけ。消えて困る進行が存在しない）
- **旧教材に紐づかない**（Questではなく `openingJa` / `openingZh` の文章だけを使う）
- 出典は既にある `chapterForArea(areaId)` → `ChapterDef.openingJa`

これなら1,400行の資産のうち「世界に来た感じ」を出す部分だけが動き出し、
サンドボックス依存も旧教材依存も持ち込まない。

### 実装（見積り）

| 触るもの | 中身 |
|---|---|
| `AdvShell.tsx` | 攻略の祝いのあとに `openingJa/Zh` を1枚出す（約25行）。`chapterForArea` を読むだけ |
| 新規テスト | ゲートにしない（読まなくても次へ進める）・保存しない・章が無いエリアでは出さない |

DB変更なし。`!advOn` のゲートは**そのまま**（Quest本体・章の進行は引き続きV2に出さない）。

### いつやるか

**100人Beta中でも、stage攻略に到達した人が出てから。**
いま到達している生徒がいないなら、物語より手前（最初の1stepに届かない25%）に問題がある。
到達人数は `learning_day` と mastery から出せる。
