# 満足度計測設計（Pilot用・2026-07-31）

方針: **コードから満足度を断定しない。** Pilot 3名の実利用で測る。
個人情報・会話本文は送らない（既存 `courseAnalytics` はイベント名+匿名パラメータのみ＝この方針に適合）。

## 1. 行動指標（既存 trackCourse を利用。★=イベント追加が必要）

| 指標 | イベント | 状態 |
|---|---|---|
| login成功率 | `login_success` / 画面表示 | ★追加 |
| first lesson開始率 | `start_ai_course_lesson`（初回） | 既存 |
| first lesson完了率 | `complete_ai_course_lesson`（初回） | 既存 |
| time to first success | login→初回complete の経過 | ★導出 |
| AI会話開始/完了率 | start/complete_ai_course_lesson | 既存 |
| 言い直し完了率 | レポート内の言い直し操作 | ★追加 |
| 復習完了率 | 復習開始/完了イベント | 既存（quickreview系） |
| Day1/3/7再訪 | 日次の初回イベント | GA4のretentionで導出 |
| error率 | ErrorBoundary表示 | ★追加（画面名のみ） |
| support到達率 | `open_support`（こまったとき） | ★追加 |
| mic許可後の離脱 | mic_granted → start無し | ★追加 |
| 画面別離脱 | 各view_*イベント | 既存 |

★は5イベント程度の軽い追加で足りる。会話本文・音声・メールは**送らない**。

## 2. ミニアンケート（アプリ内・各1〜5）

初回レッスン後（3問固定）:
1. 次に何をすればよいか分かった
2. 今日、少し日本語が話せるようになったと感じる
3. また明日使いたい

3回目終了後（4問）:
1. 自分に合った内容だった
2. 修正の説明が分かりやすかった
3. 人間のレッスン以外でも練習を続けられそう
4. 友人に勧めたい
＋自由記述1問（任意）「一番困ったことがあれば教えてください」

保存先: `ai_issue_reports` と同じ経路（本文なし・数値+画面IDのみ）で足りる。
zh表示必須。回答は30秒以内で終わる設計にする。

## 3. Pilotで検証する仮説

| # | 仮説 | 計測 |
|---|---|---|
| H1 | LPログイン導線が無くても招待URLで到達できる | login成功率・supportへの「入れない」報告 |
| H2 | Homeの第一CTAで迷わない | login→start の時間（<60秒か） |
| H3 | 施設名（日本語）が初級者の障壁になる | 書庫/工房の初回タップ率・supportでの質問 |
| H4 | イラストが語の記憶を助ける | 図鑑滞在時間・自己申告「记住了」率 |
| H5 | レポートの日本語のみ励まし文が完了体験を下げる | アンケートQ2・3回目Q2 |
