# しくみラボ Phase 2A（1単元縦切りMVP）
目的: 教材候補→人間レビュー→語彙→しくみ→小テスト→軸別結果→苦手抽出→復習候補の一連が成立するかを1単元で検証。
- 単元: 「自己紹介で使う基本のことば／自我介绍常用词与句型」（draft・語彙10=名詞6動詞3な形1・規則3・問題11=読3意3形接3使2）
- 学習軸: 読み/意味/形/接続/文中使用（合計点でなく軸別表示・満点でも完全習得と表示しない）
- 採点: 決定的（choice/かな正規化input/決定的シャッフルorder）・LLM不使用
- reviewStatus: 全data=draft固定。表示は adminOverrides.labPreview=true のテストアカウントのみ（一般・Andyさん非表示）
- 進捗: React stateのみ・「正式保存されません」を画面に明記。復習候補は純関数（誤答=翌日/ヒント正解=3日後/自力正解=なし）で導出のみ
- Phase 2B移行条件: ①しょっちゃんのdraft目視レビュー（語彙・訳・問題）②単元フローの体感確認③進捗保存方式（専用テーブルvs settings）の承認④残り5〜7単元の制作着手判断

## 遅延読み込み計画（CEOレビュー前修正§10・計画のみ／未実装）

現状: 単元データ＋Lab画面はメインバンドルに含まれ +5.3KB（許容済み）。単元が増えるとメインバンドルが単調増加するため、Phase 2B以降で以下を実施する。

1. `CourseFoundationLab` を `React.lazy(() => import(...))` 化し、`Suspense` フォールバック（既存のローディング表現を流用）でラップする。Lab入口は labPreview 管理者のみのため、一般学習者のバンドルには一切載らない。
2. 単元データ（foundationUnitN.ts）は Lab チャンク側からのみ import し、`import.meta.glob` などで単元単位の動的チャンクに分割する（1単元=1チャンク）。
3. 効果測定: `npm run build` のチャンクサイズを docs に記録し、「メインバンドルは単元追加で増えない」ことを確認基準とする。
4. 実装タイミング: 単元数が2以上になる Phase 2B の最初のコミットで実施（データ構造の変更を伴わないため独立コミット可）。
